# work-report 사용 설명

AI와 나눈 대화, git 기록, 내가 고친 파일에서 그날 한 일을 뽑아
**일일·주간 업무 보고서**를 만든다.

## 여는 법

설치를 마치면 이 화면이 저절로 열린다.
다음부터는 윈도우 키를 누르고 `work-report`를 검색해 실행한다.

내 PC 안에서만 도는 임시 서버라 다른 사람은 볼 수 없고, 두 시간 동안 아무 조작이 없으면 스스로 닫힌다.
보고서는 파일로 남으니 다시 실행하면 그대로 열린다.

## 저절로 만들어진다

**평일 17:30에 일일 보고서가, 수요일 17:35에 주간 보고서가 만들어진다.** (설치할 때 정한 시각이다.)

| 알림 | 뜻 |
|---|---|
| `일일보고 - 작성중` | 기록을 모으는 중. 1~3분 |
| `일일보고 - 완료` | 누르면 그 보고서가 이 화면에 열린다 |
| `일일보고 - 작성 실패` | 보고 폴더의 `runlog`에 이유가 남는다 |

17:30 이후에 한 일은 그날 보고서에 없다. 퇴근 직전에 `일일보고 만들기`를 누르면 그 시점까지로 다시 만든다.
PC가 꺼져 놓친 날은 다음 실행이 이틀 전까지 채운다.

## 문서 세 가지

| 갈래 | 무엇이 들어 있나 | 언제 보나 |
|---|---|---|
| 일일 보고 · 주간 보고 | 사무적 양식의 요약 | **제출할 때** |
| 한 일 목록 | 한 일과 그 근거를 사실대로 | 요약에서 빠진 것을 되찾을 때 |
| 수집 원본 | 기계가 뽑은 세션·커밋·파일 목록 | 근거를 끝까지 따라갈 때 |

## 주간 보고

**목요일부터 다음 주 수요일까지, 평일 5일이 한 구간이다.**

원본 대화가 아니라 그 기간의 **한 일 목록**을 읽어서 쓴다.
그래서 일일 보고서를 고쳐도 주간에는 반영되지 않는다. 주간까지 고치려면 같은 날짜의 한 일 목록을 고친다.
주간 보고서를 열면 제목 아래에 그 구간의 한 일 목록이 날짜별로 나오니 거기서 바로 간다.

## 보고서에 들어가는 것

Claude Code·Codex의 대화 기록, git 커밋, 그리고 **내가 고친 파일**이다.
**대화 본문은 읽지 않는다.** 세션 제목, 내가 친 지시, 고친 파일, 저장소, 시각만 남는다.

파일은 내 PC의 내 폴더에서 그날 **바뀐 것만** 본다. 열어 보기만 한 것, 남에게 받은 것,
복사해 온 것은 빠진다. OneDrive와 프로그램 설정 폴더는 읽지 않는다.

파일이나 커밋으로 확인되지 않는 것은 적지 않는다. 다음 할 일이 대화에 없으면 `익일 계획` 절이 통째로 빠진다.

## 화면

### 문서를 찾는다

| 어디 | 무엇 |
|---|---|
| 왼쪽 위 `work-report` | 가장 최근 보고서로 돌아온다 |
| 왼쪽 검색 칸 | 날짜 몇 자를 치면 그것만 남는다. `/` 를 누르면 커서가 간다 |
| 왼쪽 목록 | 최근 다섯 개와 갈래별 전체. `☰` 또는 `Ctrl+\` 로 접는다 |
| 제목 왼쪽 `‹ ›` | 같은 갈래의 이전·다음 날짜로 간다. `[` 와 `]` 도 같다 |

### 근거로 건너간다

제목 아래 줄이 **같은 날짜의 다른 문서**를 가리킨다. 일일 보고에서는 그날의
한 일 목록과 수집 원본으로, 주간 보고에서는 그 구간에 들어가는 한 일 목록들로
바로 넘어간다. 요약에서 빠진 것을 왼쪽 목록을 다시 헤치지 않고 되찾으라고 둔 줄이다.

### 읽고 고친다

| 어디 | 무엇 |
|---|---|
| `미리보기 / 원문` | 보기 좋게 그린 것과 원래 글자 |
| 표 칸을 **두 번 누르기** | 그 칸만 그 자리에서 고친다. `Enter` 끝냄, `Tab` 다음 칸, `Esc` 취소 |
| `고치기` | 왼쪽 원문, 오른쪽 결과로 나뉜다. 좁은 창에서는 `미리보기 / 원문` 으로 번갈아 본다 |
| `저장` (`Ctrl+S`) | 원래 파일에 덮어쓴다 |
| `되돌리기` | 마지막으로 저장한 내용으로 되돌린다 |
| `복사` | 본문을 클립보드에 담는다. 제출문 절이 있으면 그 절만 담고, 단추도 `제출문 복사` 로 바뀐다 |
| `제출하러 가기` | 같은 것을 복사하고 제출 화면을 새 탭으로 연다 |

**수집 원본은 고치지 않는다.** 기계가 뽑은 기록이라 읽기만 한다.

되돌릴 수 있는 것은 마지막 저장까지다. 크게 손볼 때는 `복사`로 원본을 챙겨 두면 마음이 편하다.

### 만들고 지켜본다

| 어디 | 무엇 |
|---|---|
| 오른쪽 위 `일일보고 만들기` · `주간보고 만들기` | 지금 시점으로 다시 만든다 |
| 오른쪽 아래 카드 | `기록 모으는 중` → `보고서 쓰는 중` 순으로 바뀐다 |
| 완료 카드 | 이번에 쓰인 보고서를 모두 보여 준다. 빠진 날을 함께 채웠으면 여러 개다 |

**17:30에 저절로 도는 실행도 이 카드로 보인다.** 그때 `만들기`를 누르면 `건너뜀` 으로
물러나니, 카드가 끝나기를 기다렸다가 누른다.

### 그 밖에

오른쪽 위 반달 단추가 화면 밝기를 `자동 → 밝게 → 어둡게` 로 돌린다. 자동은 윈도우 설정을 따른다.

## 설정

| 항목 | 언제 건드리나 |
|---|---|
| 작성자 | 보고서에 찍히는 이름이 다를 때 |
| 실행 CLI | claude 대신 codex로 돌리고 싶을 때 |
| 제외할 저장소 · 경로 | 개인 저장소나 임시 폴더가 업무로 잡힐 때 |
| 키·토큰 가리기 | 켜 두면 API 키처럼 보이는 값을 가린다 |
| 빠뜨린 날 채우기 | 며칠 전까지 거슬러 채울지. 휴가가 길면 늘린다 |
| 주간 마지막 요일 · 기간 | 팀의 주간 구간이 다를 때 |

바꾼 값은 **다음 실행부터** 적용된다.
`실행 파일` 칸의 흐린 글씨는 자동으로 찾은 경로이니 비워 두면 된다.

## 내 양식

회사 양식이나 우리 문체에 맞추려면 **설정**에서 `내 보고서 양식 쓰기` 또는
`내 글쓰기 문체 쓰기`를 켠다. **켜는 순간 기본값이 복사돼 생기고**, 왼쪽 아래
`내 양식`에서 열어 고치면 다음 보고서부터 그 양식으로 나온다.

- **보고서 양식** 은 양식을 통째로 바꾸고, **글쓰기 문체** 는 기본 원칙 뒤에 덧붙인다.
- 끄면 기본값으로 돌아간다. 고쳐 둔 파일은 지워지지 않으니 다시 켜면 그대로 쓴다.
- **꺼 두는 것이 기본이다.** 켜면 그 양식은 그 시점에 멈추고, 꺼 두면 업데이트로 좋아진다.
- **업데이트해도 지워지지 않는다.** 보고 폴더 안이라 설치도 제거도 손대지 않는다.
- 파일이 비었거나 글자가 깨지면 **기본값으로 돌아간다.** 이유는 그날 수집 원본 맨 위에 적힌다.
- 확인 질문을 하지 않는 것, 근거 없는 내용을 쓰지 않는 것은 여기서 바꿀 수 없다.
- **제출문 절의 모양도 바꿀 수 없다.** PMS 폼의 칸 구조라서 도구가 쥐고 있다.
  무엇을 얼마나 쓸지는 `보고서 양식`의 `제출문 절에 무엇을 쓰나`에서 고친다.

`내가 쓰던 대로 쓰기`는 파일이 없다. 켜면 PMS에서 받아온 내 지난 제출문의
**끝맺는 말과 어휘**를 따른다. 받아오는 것은 설정의 `지난 제출문 가져오기`가 하고,
받아온 것이 없으면 켜 두어도 아무 일도 하지 않는다. 분량과 말투는 `보고서 양식`이
정하므로, 과거와 다르게 쓰고 싶으면 거기를 고친다.

## 잘 안 될 때

| 증상 | 볼 것 |
|---|---|
| 알림이 안 뜬다 | Windows 알림 설정에서 `work-report`를 켠다. 집중 지원도 끈다 |
| 보고서가 비어 있다 | 그날 기록이 없거나 CLI 로그인이 풀렸다 |
| 작성 실패 알림 | `runlog\<월>\<날짜>-daily.log` 마지막 줄 |
| 어제 것이 없다 | 오늘 실행이 채운다. 급하면 `일일보고 만들기` |

파일은 `%USERPROFILE%\work-report` 아래 월 폴더로 쌓인다. **보고서는 지우지 않는다.**
